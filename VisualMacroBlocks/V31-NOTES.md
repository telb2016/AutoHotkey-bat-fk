# V31 notes (rules as columns: Only when, otherwise, If it fails, Skip / Stop / Wait until window)

File: VisualMacroBlocks-makecode-telek-V31-onlywhen.ahk2 (copy of V30-listsheet). Self-test: `Failures: 0`, **834 PASS** (V30 had 724).
All new code is one section `V31_*` above the "V4 STARTUP" line (plus small hooks listed below). New controls: none in `s.Ctl`; the rule builder is a separate small window (`s.RuleDlg`).

## Done
- **V30 leftover: stop after 3 bad rows in a row.** Runner `foreach` with the `v30` flag counts rows that failed (a row in `RowLog` when the row ended in `nextrow`); a row skipped on purpose (a checkpoint "No", `Skip this row`) does not count. Pure `V31_BadStreak`, `V31_StreakStop`, `V31_StreakSentence`, `V31_StreakSummary`. The runner sets `StopNote`, `VM_Play` uses it as the message, `V30_AfterRun` shows `Stopped after row 3 of 10: 0 done, 3 skipped (rows 1, 2, 3). 3 rows in a row could not be done - stopped so the rest are not skipped too.` Old hand-made For each blocks are unchanged (tested).
- **Item A, Only when.** New grid column **Only when** (stored as `when`, shown `always` when blank) and **If it fails** (stored `onFailStep`), right after Repeats: the grid has **25** columns now (the V27 "23 columns" check, and two V29 column-order checks, were changed to 25; V10 det-block count 9 -> 10 for the new Wait until window block).
  Pure parser `V31_ParseRule(text, names)`: `Status = On`, `Amount > 100`, `>=`, `<`, `<=`, `<>` / `!=` / `is not`, `is`, `Name is empty` / `is not empty`, `Name contains x` / `does not contain x`, `# > 1`, `window Save As is open` / `is not open` (title contains, any program); quotes optional; two or more parts joined by only `and` or only `or` (mixing is refused with a sentence). Column names with spaces work (longest known name wins). Text compares ignore case; two numbers (also `1,250`) compare as numbers; `<` `>` with an empty side are false. `V31_Test(rule, lookupFn, winFn)`.
  Cell editor (V28) rules: `V31_CheckWhen` refuses an unknown name (sentence lists the names you can use) and an `otherwise` with nothing above it. Delete / Ctrl+X clear the two new cells too. Right-click an Only when cell: `V31_CellMenu` (Build a rule..., otherwise, always, Type a rule...). The builder window (`V31_RuleBuilder`, `V31_BuildRuleText`, pure) picks name / comparison / value.
  Runner: `V4Runner.Run` asks `V31Infos(list)` (cached chain info per list; `""` when no step in the list has a rule, so old macros take exactly the old path) and `V31Allowed` before a step starts. A step left out by its rule is not a failure, not counted as a bad row, writes no note (`WhenSkipped` counts them). Values for a rule: current list row first, then runner variables, then built-ins; `#` is `LoopIndex` (row / round number). A rule that cannot be read or names something unknown **stops the run** with the plain sentence (not treated as false).
  Grid: preview for the Preview row (`V31_PreviewFor` -> grey row + the cell says `→ skipped for row 2` / `round 2`; a rule that cannot be worked out is not greyed and shows a warning sentence). Only when old macros without list / Run switch show nothing.
- **Item B, otherwise.** Pure `V31_Chains(steps)` (chain id, branch, kind if / elseif / else, first step of branch, rule text, error), `V31_Decide`, `V31_NeedsRule`, `V31_Gate` (the one decision used by the runner AND the preview). Same rule text in a row = same branch (many steps per branch); a step without a rule ends the chain; a switched-off step is skipped over; a second `otherwise` after a plain `otherwise` is an error ("could never run"). Grid: a 6 px colour bar at the left of the Only when cell, one colour per chain (custom draw, `V31_ChainColor`, `V31_DrawBar`), grey text for rows left out for the preview row. The else-if rule is only evaluated when no earlier branch ran.
- **Item C, If it fails.** Drop-down: `macro setting` (stored blank) / `ask me` / `stop` / `skip this step` / `skip this row` / `try 3 times, then stop` / `try 3 times, then skip row`. Pure `V31_FailPlan(stepChoice, macroPolicy, triesDone)` -> `retry` / `stop` / `skip` / `nextrow` / `ask` / `macro` (blank = do what V30 did). "3 times" = 3 tries in all (the failed first run is try 1); a retry waits 1 s (Esc stops) and re-runs only that step. `skip this row` outside a row (no list running) stops the run. Not used while the step debugger is stepping (it keeps asking in its bar).
- **Item E.** Steps: **Skip this row** = Flow control `stop` with action `continue`; **Stop the run** = `stop` with `endrun` (Action column shows the plain words). **Wait until window** = new block `det_wait_window` (title contains / closed / seconds; fails after the seconds, so If it fails applies; Text cell: `Save As is open within 5 s`). Right-click a row -> **Add step**: Type text, Press keys, Wait (seconds), Wait until window..., Skip this row, Stop the run; inserted below the current row with plain starting values (edit them in the cells). "Skip this row" counts as done, not as a bad row.
- **Extra from the coordinator: plain Blocks toolbox.** `VMB_OnCustomDraw` no longer paints the toolbox colours while `PlainList` is on (pure `V31_PalColors`); the "Coloured rows" toggle switches both. Screenshot `V31-toolbox-plain.png` (Easy mode).
- Version text: line 1, both window titles, "NEW IN V31" in `V4_Help` and `V17_EasyHelp`, the rules paragraph at the top of `V17_EasyHelp` (without the Values sentence, see below). PC-TEST-ALL.md section 7 "Rules".

## Item D - Values sheet, ask at start, counts up, today's date, Remember (V31.1)
Header line `; V31.1 = ...` under the V31 block. Self-test: `Failures: 0`, **871 PASS** (V31 had 834: 37 new `V31.1` checks; one existing number changed: the "add step" check counts 7 kinds instead of 6). Grid columns and blocks: unchanged (no new column, no new block type; Remember is a `set` block with `remember: 1`).
- **Stored**: `settings["values"]` = Array of `Map("name", .., "value", .., "when", "fixed" / "ask" / "date" / "counts")`. Old macros have none: every new code path is gated on `V31_ValuesOf(settings).Length` (or on the runner finding nothing), so they load, show and play as before (self-test checks the runner builds nothing for them).
- **Third tab [Values]** (`V31_BuildValues`, `V31_PlaceValues`, called from `V30_Build` / `V30_Place`; `V30_SetSheet("values")`). Controls are in `s.ValBar` / `s.ValLV`, not in `s.Ctl`. Rows Name | Value | When, buttons Add value / Delete value, double-click / F2 / Enter / typing opens an overlay editor (an Edit; a drop-down for When), Enter / Tab / Shift+Tab / Esc, Delete empties a Value, Ctrl+C copies, Left / Right choose the column, its own undo (`s.ValUndo`, Ctrl+Z / Ctrl+Y on that sheet). Reused from the List sheet: `V30_CellRect`, `V30_EnsureVisible`, `V30_HitCell` now take an optional list view; the overlay-editor / own-undo pattern is the same. Hotkeys are under `#HotIf V31_ValFocused()` / `V31_ValEditFocused()` (true only while the Values grid / its editor has the focus in this window and nothing is recording or playing). `V27_PlaceGrid` now shows the Steps grid only when `s.Sheet = "steps"` (it used to test `!= "list"`).
- **Names** (`V31_ValueNameError`, pure): letters, digits, `_`; refused with a plain sentence: empty, `#`, a name with other signs (the sentence offers `my_name`), a name the program uses (`clipboard`, `date`, `time`, `row`, `index`), a List column (any case), another value. Renaming a List column to a Value's name is refused too. Renaming a Value changes `{{old}}` in Type texts and the name of Remember steps (`V31_RenameInSteps`; one `VMB_Snapshot`; Ctrl+Z on the Values sheet puts the Values back but not the steps - use Ctrl+Z on the Steps sheet for them, as the List sheet does).
- **`=name`**: `V30_ToStored / V30_ToShown / V30_TextCell` get `V31_NamesAll(settings)` (List columns first, then Values) instead of only the columns, so Type cells, the cell editor, the "Use list column" menu, the Preview row and the rule parser (`V31_NamesNow`, `V31_PreviewFor`) all know Values. `V30_Gate` is true when the macro has Values. Stored as `{{name}}`, as with columns.
- **Run time (editor AND exported player share it)**: `V4Runner.V31Init(asked)` builds `Vals` (fixed, ask at start = the answer or the shown Value, today's date = `FormatTime` with the format in Value, default `MM/dd/yyyy`, worked out once) and `Counts` (counts up: start + round - 1, worked out when used; `LoopIndex` is the round / row number in a list / times run, a once run stays at the start value). Lookup order: current list row, then Values, then runner variables (`Lookup` for `{{name}}`, `V31Value` for rules; a rule can use Values). A Remember step also sets the Value (a counts up one stops counting after it).
- **Ask at start**: `V31_AskForm` (one small form, label = name, box = current value, first box has the keyboard, Enter / OK keeps or changes, Cancel / Esc / close stops) is called from `VM_Play` before the runner is made, so it works in the editor and in `V4_Start`'s player with no extra code there. Cancel returns `Stopped before step 1: the Values form was cancelled.` and runs nothing. `opts.Asked` (a Map) skips the form (used by the self-test).
- **Preview row**: `V31_PreviewRow` pads the list row and adds one cell per Value; the Text cell shows `=greeting → "Hello"`, `=n → "11"` (start + row - 1), `=who → "friend"` (the current value). Rule preview (grey rows) uses the same row.
- **Remember** (`V31_ParseRemember`, `V31_NewRemember`, `V31_IsRemember`, `V31_RememberText`): `clipboard as name` / `"text" as name` (a leading word Remember is fine; a text that is exactly `=Column` becomes `{{Column}}`, `{{...}}` stays). A `set` block with `remember: 1`, so the old runner `set` case does the work; the grid shows one plain row (Action `Remember`, Text `clipboard as total`), editable in the Text cell. A new name creates its Values row (`V31_AfterStepEdit`, editor only; at run time a name without a row still works through the runner variables). Added to the right-click **Add step** menu as `Remember clipboard as...`.
- Help: Values sentence in `V17_EasyHelp` (the one the first round left out) and a `NEW IN V31.1` paragraph in `V4_Help`. PC-TEST-ALL.md section 7 items 9-12.
